# Crate charter: `anneal-cli`

## Purpose
The `anneal` binary: the deterministic layer behind the plugin's hooks and skills. It is the composition root, so argument parsing, output formatting and exit codes live here. Domain logic moves into library crates when a second consumer appears (ARC-07).

## Layer
binary. Owns process concerns: arguments, stdout and stderr, exit codes. The code lives in an internal library target (`anneal_cli`, `src/lib.rs`) so tests and doctests can reach it; `src/main.rs` only passes the process's arguments and streams to `cli::run`.

## Allowed dependencies
- Workspace crates: `anneal-ledger` (event registry and store).
- Third-party: `clap` (derive; command tree and help), `serde` and `serde_json` (envelope, snapshots), `thiserror` (error enums), `sha2` (content hashes for the lint snapshot), `ureq` (3, `rustls` only: Clef's HTTP transport); dev: `tempfile`. Each addition is an H-16 decision recorded below.
- Never: anything that needs a network at build time.

## Public surface
The contract is the command line, the JSON envelope on stdout and the exit codes in `docs/exit-codes.md`. The `anneal_cli` library is internal (`publish = false`) and not a stable API.

## Invariants
- `--help` and `--version` exit 0 (only as the last argument); a usage error exits 2 and writes nothing on stdout.
- Every error is exactly one `ERROR <reason>` line on stderr, and nothing on stdout.
- No failure exits 0; the envelope's `ok` is true exactly when the exit code is 0. The one exception is `anneal hook <name>`, which fails open: it notes its failures in its output (or in one `ERROR` line on stderr when stdout cannot be written) and exits 0; only its usage errors exit 2 (`a_closed_stdout_still_exits_0_with_one_error_line`). ## Errors
Usage errors exit 2 (as do `task done` and `repro record` when their command cannot be started and every `floor-guard` tool error, each with its own row in the command's table; `decide`'s refused state, question, options or label are usage errors too), 64 for a command not implemented (no command returns it since #36 retired the last stub; `CliError::NotImplemented` and the code are kept pending wi-720c2d), internal errors (git, snapshots, the ledger store, a tracker that cannot be read, `decide`'s thresholds file, log or clock, `calibrate`'s log, thresholds or proposals file, except no proposals file for `--apply`, a usage error) 70, a target `watch` cannot read (gh failing, a missing pull request, commit or deployment, an answer it cannot decode, a closed pull request, too many items) 7 (`WatchError`, `exit_codes::WATCH_QUERY`), `rollout`'s, `perf`'s and `migrate`'s unreadable inputs as their docs say (`RolloutError`, `PerfError`, `MigrateError`: a missing or invalid file or argument 2, a file that exists but cannot be read, a failed run or an unwritable file 70), and a write failure on stdout or stderr 74. `orchestrate park` fails open rather than erroring when weigh-in cannot park (exit 4, an outcome); its ledger failures are 70. `eval routing --router claude` fails with 4 (`RouterError`, `exit_codes::EVAL_ROUTER_FAILED`) when the real router cannot run its first batch (including a result in another schema version, of the wrong shape or with a negative cost, and a failure to wait for `claude`), 70 when its temporary workspace cannot be made, and with a usage error (2) for a `--changed-since` base that names no commit. `eval uplift` fails the same way (`UpliftError`, `CliError::Uplift`): 4 when its first batch cannot run, 70 for its workspace (a `--baseline` that cannot be copied included), 2 for a `--changed-since` base that names no commit, a missing suites or skills directory, a `--skill` with no suites, a `--baseline` whose plugin manifest cannot be read (`UpliftError::Baseline`), or selected cases naming gated tools without `--allow-gated-tools` (`UpliftError::GatedTools`). A command's own outcomes (cycle, red test, findings) are envelopes with per-command codes, not errors.

## Test strategy
Unit tests beside the code for parsing and output; integration tests in `tests/it/` run the built binary. Run with `cargo test -p anneal-cli`. `tests/it/repo_gates.rs` runs the repository's own `plugin/skills` and `evals/routing` against the Tier 0 and Tier 1 bars, so CI's `cargo test` enforces them. `tests/it/dry_run.rs` replays the recorded define chain in `evals/fixtures/dry-run/` (grill, spec, plan, tickets) on a temporary copy and compares the ledger events with its `events.jsonl`; a change that alters an artifact or an event re-records the fixture (its README says how).

## Do not
- Do not print with `println!`; write through a locked handle.
- Do not open the ledger anywhere but through `anneal_ledger::Store`, and do not resolve its path anywhere but `paths::ledger_store` (or `paths::ledger_store_within`, its variant with a caller's git timeout).
