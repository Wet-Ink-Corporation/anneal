# Changelog

All notable changes to anneal are recorded here. A release renames `## Unreleased` to `## <version> — <date>`; that section is the release notes.

## Unreleased

- `anneal eval uplift --allow-gated-tools`: a Tier 3 run whose selected cases name `Write`, `Edit` or `Bash` is now refused unless this flag is given, before anything is copied, spent or run (exit 2, one `ERROR` line naming the flag and the case files, nothing on stdout). With the flag a run grants them as before, still listing them in `data.granted_tools` and the `eval/uplift/granted-tools` finding; a selection with no such case needs no flag, and `--check` refuses the flag as it does every run flag. The seed `build` suite names `Bash`, so a full run needs it.
- Learn-phase skills, all user-invoked (`disable-model-invocation: true`, outside the listing budget): `/anneal:correct` fixes a mistake or review finding at the highest level that holds (architecture, then types, then a lint that names the fix, then a test, docs last), applies the "would a future engineer still repeat this?" bar, and emits a hook entry, lint or test rather than prose, recording each rule with its enforcer; `/anneal:write-skill` writes a skill test-first from a case that fails with no guidance, in skill-creator's structure, and merges only once Tiers 0 to 3 pass (`anneal lint skills`, `anneal eval routing`, `anneal eval routing --router claude`, `anneal eval uplift`); `/anneal:calibrate` runs `anneal calibrate`, explains each point's verdict, shows the proposed thresholds as a diff and applies them only on the human's yes.
- `anneal lint rules <file>... [--root DIR] [--hooks FILE]` checks rule documents: every list item under `## Rules` must name, after `Enforcer:` and in backticks, an enforcer that exists: `anneal <command> ...` (down to a command that runs), `hook <id>` (an id of `hooks.metadata.json`) or `test <file>::<fn>` (a regular file that resolves, symlinks followed, inside the root and defines that function). Several may follow one label as a comma-separated run, each checked; the default hooks metadata is read only when it resolves inside the root. A rule with none, or with one that cannot be found, is a rule-10 `enforcer` error (exit 1), in the same finding model and envelope as `lint skills`. See `docs/skill-rules.md`.
- `anneal calibrate` now shows each proposed threshold as the changed line of the thresholds file (`data.diff`), and `anneal calibrate --apply --thresholds <file> [--point Dn]` writes the last run's proposed thresholds into that file, number by number, keeping its layout. It writes nothing, and exits 3, when a step's pointer is not under its own point and question, a pointer no longer holds the proposal's current value, or the result would not read back; mode changes are never applied (they are listed in `data.not_applied`). `--apply` with no proposals file is a usage error (2): run `anneal calibrate` first. A proposal that does not apply to the file read leaves `data.diff` empty and says why in `data.diff_error`. Without `--apply`, `calibrate` still never writes a thresholds file. See `docs/calibrate.md`.
- `anneal eval uplift` (Tier 3) measures whether each skill changes what the agent does: every case under `evals/uplift/<skill>/{regression,capability}/` runs 3 times through `claude plugin eval` against the whole plugin and 3 times against a copy with that skill removed (or a `--baseline <plugin dir>`), in a temporary workspace, within `--max-cost-usd` (default 25) and `--timeout` (default 3600 s). A skill passes when its pooled uplift has a 95% Newcombe lower bound of 0 or more, every guard case passes all 3 runs with the skill (pass^3), and no regression suite falls confidently below 90%; assertions that pass in 90% or more of baseline runs are listed as non-discriminating, and capability suites at 100% as graduates. Cases are JSON with pressure fixtures (authority, time, sunk cost) and `claude plugin eval`'s graders, deterministic first and `llm` last. Exit 0 pass, 1 below bound, 2 invalid suites, 3 incomplete, 4 `claude` could not run. It shares Tier 2's safeguards: a private workspace, a refused batch that reports more runs of a case than it asked for, a spend reported as unknown or a lower bound when `claude` failed after starting, and a time limit that counts the plugin copies. The with arm may spend at most half the cost cap, so the baseline always has the rest. A run passes only when every grader of its case passed; a result that names a grader the case does not have, lists one grader twice in a run or lists a case twice is refused (its reported cost still counted), and cases the batch did not ask for are dropped. With no case selected nothing runs and the run is reported skipped (exit 0); a skill directory with no suite, or with `--` in its name, is an invalid suite (2). Cases that name `Write`, `Edit` or `Bash` are granted them from their files alone, so they are listed in `data.granted_tools` and an `eval/uplift/granted-tools` finding. A skill is removed from the skills directory `--skills` names, and no copy keeps an `anneal-uplift-*` directory left in the source plugin. A `--baseline` whose plugin manifest cannot be read is a usage error (2); its results are checked under that manifest's name. `--check` validates the suites and runs nothing (`cargo test` runs it over the repository's 27 seed cases, which cover all seven entry skills); `--changed-since <ref>` runs only the skills whose files or suites changed. The model-change re-run for retiring scaffolding hooks and the CI job, pending a maintainer and an API key, are in `evals/README.md`. `anneal eval`'s exit-code table is now headed `anneal eval`, its meanings covering both suites.
- `anneal eval routing --router claude` (Tier 2) measures how often each skill really fires under Claude Code's router: it runs every positive routing fixture through `claude plugin eval` (one `tool_used: Skill` grader per skill, paired with an outcome grader; no baseline arm) in a temporary copy of the plugin, 3 runs per prompt and 3 more while its interval straddles the bar, up to 12, within `--max-cost-usd` (default 25, a cap on starting batches that runs in flight can overshoot) and `--timeout` (default 3600 s). Each skill passes when every one of its own prompts settles with a 95% Wilson lower bound of 0.70 or higher and the upper bound pooled over its siblings' prompts is 0.20 or lower; a run that ran out of turns counts as a trial, another errored run only when a skill fired; the report lists each skill's intervals and the confusion matrix. Exit 0 pass, 1 below bound, 2 invalid fixtures, 3 incomplete (cost cap, time limit), 4 the router could not run. On Windows pass `--claude <path to claude.cmd>`. The plugin's hooks run on the host during the eval, so run it in a container. A run whose temporary workspace could not be removed still exits 0 with an `eval/routing/cleanup` finding. `--changed-since <ref>` skips the run (exit 0) unless a skill's description, `when_to_use` or the skill set changed. `anneal eval routing` without `--router` is Tier 1, unchanged. The CI job that runs it on pull requests is drafted in `evals/README.md`, pending a maintainer and an API key.
- `anneal verdict set --pr <n> --sha <rev> --level <tests-verified|reviewed|approved> --source <local|review-plugin|human> [--base <ref>]` records a `verdict_set` with the full commit, the base and the change's `git patch-id --verbatim`. `anneal verdict valid --pr <n> [--head <rev>] [--base <ref>]` exits 0 when the latest fresh verdict is a level, 3 when it is `noise_only`, and 1 with no verdict, only stale ones, or a fresh `changes_requested`; a verdict stays fresh across a rebase that leaves the change's content as it was (same patch id from the same base). The ledger registry is now version 6 (`verdict_set` gains the levels `tests_verified` and `reviewed` and the optional `source`, `sha`, `patch_id` and `base`). See `docs/verdict.md`.
- `anneal ship skip-rule [--base <ref>] [--head <rev>]` exits 0 (skip full review) when `git diff --numstat` against the base shows at most 2 files, fewer than 50 changed lines, no binary file and no sensitive path (auth, payments, migrations, CI, infra and the gate's own configuration by default, plus `ship.sensitive_globs` from `.anneal/config.json`), else 1 with the reasons listed.
- `anneal hook merge-gate`, a fail-closed `PreToolUse` hook on Bash (`onFailure: "block"`, 5 s timeout): denies `gh pr merge`, found through the guard's lexer and unwrapping with gh's arguments read as its flag parser reads them, unless the pull request, named by number or by a `/pull/<n>` URL of the worktree's `origin` (no `-R`, `GH_REPO` or `GH_HOST`), is pinned with `--match-head-commit <full commit>` (the denial names the command) and has a fresh tests-verified-or-better verdict for that head and, unless the skip-rule skips the change, a review verdict. A human `approved` counts as the review while `review.require_plugin` in `.anneal/config.json` is `false` (the default); once it is `true` only the review plugin's verdicts count. Each denial is one `ERROR` line naming the command that records the missing verdict, plus a `gate_blocked` event; the hook never creates a ledger.
- Clef reaches Workers AI over HTTPS: `anneal decide`, `grill classify` and the guard, route and ruled-before hooks now send through a ureq 3 + rustls transport (bundled Mozilla roots) instead of reporting every call unreachable. Each call is bounded by the 2 s timeout, follows no redirect, ignores proxy environment variables and reads at most 64 KiB of response; the token is sent only in the `Authorization` header and never appears in errors, rows or envelopes. Every point still starts in shadow. An `ANNEAL_CLEF_URL` override for tests is read only by debug builds and only on `127.0.0.1` or `[::1]`; release builds ignore it.
- Redaction (guard and prose): a cookie or other header-shaped credential with its value attached (`Cookie:a=x; sid=S`, `X-Api-Key:k`) hides that value and, after a `;`, the cookie pairs that follow, but no other word (`docker run -v db-password:/p alpine rm -rf /p` and `git push origin fix-auth:main --force` keep their commands readable), a cookie pair whose value holds a blank or `;` or opens an unclosed quote is not hidden (`c='rm -rf ~'`), every cookie pair after an unquoted header in prose is hidden (`Cookie: a=1; b=2; c=3`), and a cookie pair after a `;` with a quoted value (`sid="S"`) or ending in a closing quote (`sid=S'` inside `bash -c "…"`) is hidden too; still no command after a separator is hidden. `docs/guard.md` now notes that a non-pair word after a `;` in a header value ends the hidden pairs, and that `https://host:8080?to=a@b` loses `host:8080?to=a`.
- `anneal watch pr <n>`, `watch ci <ref> [--repo owner/name]` and `watch deploy <id> [--provider github] [--repo owner/name]` long-poll a pull request, a commit's checks or a deployment through `gh` (read-only) until it settles or `--timeout <secs>` passes (default 1800 s; backoff 10 s doubling to 60 s), then exit with one code: 0 clear, 2 merge conflict, 3 unresolved review threads, 4 failing checks or a failed deployment, 5 timeout, 6 a draft, a `mergeable_state` GitHub will not merge (branch protection still `blocked` once every check passed, `behind`) or the merge gate would deny GitHub's head, 7 the target could not be read. A pull request is clear only on `mergeable_state` `clean` or `has_hooks`; `unstable`, and `blocked` while checks run, keep the watch waiting. `watch ci` resolves its ref to one commit per poll and reads every check of that commit. The envelope names every blocker (`data.blockers`, one finding each) and what was still pending. Deployments are read through a pluggable provider, starting with GitHub Deployments. Ctrl-C ends a watch at once with the signal's status. See `docs/watch.md`.
- `anneal hook injection-scan`, a fail-open `PostToolBatch` hook (`onFailure: "continue"`, 2 s timeout) that never blocks: it scans what the batch's `Read` and `WebFetch` calls returned (the first 256 KiB of each, 4 MiB per batch) for instruction-shaped text (overrides such as "ignore all previous instructions", directives addressed to an AI, hidden HTML comments that direct one, chat and tool-call markup and tool-call JSON outside code fences, invisible characters: Unicode's default-ignorable set, with emoji, joiner, keycap, soft-hyphen and right-to-left uses exempt) and adds one `additionalContext` line naming the first hit's `file:line` (or URL and line) and the hit count, saying the content is data; a path or URL that is itself instruction-shaped, percent-decoded or not, is not repeated, and invisible or line-breaking characters in it are escaped. It is silent on a pass. On its corpus of 15 positives and 16 benign lookalikes it flags every positive and no lookalike (false-positive rate 0%). See `docs/injection-scan.md`.
- Surviving compaction: `anneal statusline` (set once as the status line in `~/.claude/settings.json`; the README has the setting) prints `anneal ctx 120k/200k 60%` and saves each session's context usage to `~/.anneal/context-usage.json`, measured against the auto-compact window (`CLAUDE_CODE_AUTO_COMPACT_WINDOW`, else the model's window, else 200,000 tokens); it fails open. The `context-monitor` hook (`PostToolBatch`, fails open) reads it and warns once at 60% and stops once (`decision: "block"`) at 75% of the window per crossing, re-arming when usage falls back; with no status line it is silent and the session start shows a one-time setup hint. The `handoff` hook (`PreCompact`, fails open, never blocks) writes `.continue-here` at the repository root (phase, task N of M, open gates, a ledger summary, the `/compact` instructions, and any `## Notes` kept from the last one), lists it in the repository's `.git/info/exclude` so the tree stays clean, and records its hash in the anneal home; the bootstrap injects only a note the hook wrote, framed as data and checked by the injection scan, at the next session start. The user-invoked `/handoff` skill chooses between continue, clear, hand off, a subagent and compact at a phase boundary. See `docs/handoff.md`.
- The `ship` skill, model-invoked: review depth from `anneal ship skip-rule`, the verdict ledger through `anneal verdict valid`, GO or NO-GO only with a rollback plan, then merge, migration and rollout. `references/migrate.md` covers expand, migrate, contract with the wave tracker; `references/release.md` gives rollout stages, bands and error-budget thresholds as tables. Its Tier 1 fixture is `evals/routing/ship.yaml`; `verify` now names it as `(use \`ship\`)`, and `route.json`'s `ship` phase has `ship` as its entry skill.
- `anneal rollout decide --metrics <json> --bands <file>` exits 0 go, 1 hold, 2 rollback: each metric is rated against its band (a threshold belongs to the worse band), a banded metric missing from the input holds, and the worst band wins. See `docs/rollout.md`.
- `anneal perf sample -n <N> --out <file> -- <cmd>` saves a baseline's run times; `anneal perf noise -n <N> --baseline <file> -- <cmd>` keeps the change (exit 0) only when Welch's 95% interval on the difference of means is wholly below zero, and reverts (exit 1) when it is neutral or slower. `-n` is 2 to 100, each run has a timeout. See `docs/perf.md`.
- `anneal migrate start|done --migration <id> --wave <n>` and `anneal migrate contract --migration <id>` track a migration's waves in the ledger; contract is refused (exit 1, nothing recorded) while any wave is open, and out-of-order steps exit 3. The ledger registry is now version 7 (`migrate.wave.started`, `migrate.wave.done`, `migrate.contract`, tag `migration:`). See `docs/migrate.md`.
- `anneal brief build --ticket <id> --base <ref> [--field <key>=<text>]... [--waits-on-ci]` writes `.anneal/briefs/<id>.md`, a brief with nine fields (Goal, Repository, Owned scope, Do not touch, Invariants, Success criteria, Verification, Edits allowed with the no-revert rule, Return contract; a default re-authored from pstack's worker brief, open for Ryan), and `.anneal/briefs/<id>.review.md`, a review package with that contract and `git diff <base>...HEAD`. Stable fields come first; the commits, `cacheTtl: 1h` (with `--waits-on-ci`) and the build time last. A base that names no commit or is not an ancestor of `HEAD` exits 2 and writes nothing. `anneal lint brief <file>` exits 1 when a field is missing, repeated or empty. See `docs/brief.md`.
- `anneal hook brief`, a fail-closed `PreToolUse` hook on the Agent tool (`onFailure: "block"`, 5 s): no brief, no spawn. A spawn's prompt must name, on one `Brief: <path>` line, a brief under `.anneal/briefs/` of the worktree that passes `lint brief`; a spawn from inside a subagent is denied unless its agent type is in `orchestrate.leads` of `.anneal/config.json` (default `orchestrate-lead`). Each denial is one `ERROR brief:` line plus a `gate_blocked` event.
- `anneal hook standing-orders`, a fail-open `SubagentStart` hook (5 s): adds `.anneal/standing-orders.md` (at most 16 KiB) to every subagent's context; silent when the file is missing.
- `anneal round start|status --ticket <id>`: the fix-loop round counter, read from `round_started` events so it survives compaction. Rounds 1 to 3 go back to the same agent, rounds 4 and 5 to a fresh agent one model tier up (`context: fork` with a named subagent), and after round 5 the ticket is parked (exit 3; `start` records nothing). The ledger registry is now version 8 (`round_started` gains an optional `ticket`, and its `pr` is optional).
- The guard now denies Bash writes to `.anneal/config.json` and removing or moving `.anneal`, as for `.claude/settings*.json`: the file holds the orchestrate leads and the merge gate's settings. The preconditions hook now denies the Edit and Write tools on `.anneal/config.json` in every mode and with none (`preconditions.settings`), so a human edits it. Ticket names for `brief build` and `round` are lower-cased, and names ending in `.review` or that are Windows device names are refused.
- `/anneal:orchestrate`, a user-invoked skill (`disable-model-invocation: true`): runs an approved plan's ready tickets across subagents, each with a brief, a fresh verifier that never sees the implementer's claims, and at most five fix rounds; every judgment call goes through Clef D2, and is parked in weigh-in or ruled on and recorded, never asked in chat. See `docs/orchestrate.md`.
- `anneal orchestrate fan-out [tracker flags]` exits 0 only when `dag frontier` has 3 or more independent tickets, else 3 (fan-out refused; work one ticket at a time).
- `anneal orchestrate park --ticket <id> --q <question> --default <option> --flip <fact> --at <path:line> --resolve-by <YYYY-MM-DD>`: the weigh-in bridge. It finds `weighin` through `$WEIGHIN_BIN`, else `PATH`, pipes one `weighin batch` (a one-way raise and its deferral with the default), reads the minted `wi-` id from the receipt and records `weighin_parked`; a retry, or a park racing another of the same item, names the same item and records nothing more. A `--resolve-by` day that does not exist (`2026-02-31`) and a text holding an invisible, format or line-separator character are usage errors. With weigh-in absent or failing it records `bridge.unavailable` with the reason and exits 4, and the orchestrator rules instead. `anneal orchestrate rule --ticket <id> --what --why --cost` records `orchestrate.ruled`. The ledger registry is now version 9 (`weighin_parked`, `bridge.unavailable`, `orchestrate.ruled`, each tagged `task:<ticket>`).
- The `ruled-before` hook (Clef D6) also offers the items `weighin open --all --json --top 4096` lists as decided (weigh-in lists 12 by default; a listing of 4,096 or more is refused as possibly cut) before their decision atoms are written, so a ruling made with `weighin decide` is surfaced on a later prompt; with no `weighin` it is skipped, and a failing one adds one `ERROR` note while the other rulings are still offered.
- Clef D4 in the `completeness` (Stop) hook, in shadow: after its deterministic checks, when the final message holds a status block, it asks Clef (the larger `clef` model) whether each required section (Gate, Review, Changed, Decisions needed, Not verified) is present and grounded in the worktree's ledger, all sections at once and only while Clef's 2 s fits in the hook's first 25 s. Only once D4 enforces (configured `enforce` and past 50 answers) does a section below 0.50 block the stop, naming it, within the existing cap of 2 blocks in a row (`stop_blocked` `completeness.grounded`); in shadow, and whenever Clef is off or fails, the hook's output is unchanged. The decision rows keep no report text.
- `anneal verify risk [--base <ref>]` (Clef D5), which the `verify` skill now runs before its doubt pass: exit 0 runs the doubt review, 3 skips it, 2 means the change could not be read. Deterministic triggers apply at once, Clef or not: an auth, payments or migrations path (the skip-rule's default globs), more than 400 changed lines, or an untracked file over 1 MiB. Clef's `defect_risk` score (`clef-flash`) can skip the review only in enforce mode, with no trigger fired; in shadow, the default, the review always runs. See `docs/decide.md`.

## 0.0.1 — 2026-10-12

- Plugin skeleton: marketplace and plugin manifests with `userConfig` (`cf_account_id`, `cf_api_token` as a secret, `clef_mode`), empty hooks manifest, and the `libexec` launchers (`anneal`, `anneal.cmd`) that pick the build for the platform and fall back to PATH.
- Rust workspace (edition 2024, toolchain 1.98.1) with temper's rust-craft lints, and a scaffold `anneal` binary that answers `--help` and `--version`.
- `anneal` CLI core: a command tree with a stub (exit 64) for every v0.1 command, a JSON result envelope (`ok`, `command`, `data`, `findings`, `proves`, `does_not_prove`), per-command exit codes shown in `--help` and generated into `docs/exit-codes.md`, and one `ERROR <reason>` line on stderr for every error.
- `anneal lint skills [paths]`: checks skill directories against the 21 skill design rules (`docs/skill-rules.md`). Every finding has a rule, a checker id, `file:line` and a fix string; severities are error (exit 1), warning and review (listed, exit 0). Frontmatter is hand-parsed, `--cache` replays unchanged skills by content hash, and CI lints `plugin/skills`.
- `anneal ledger append|query|tail|journal`: an event ledger at `<git-common-dir>/anneal/ledger.sqlite3`, shared by every worktree, on happenstance's SQLite event store under a TRUNCATE journal (never WAL). Events are validated against a versioned registry (`test_run`, `task_done`, `plan_approved`, `grill_confirmed`, `repro_red`, `verdict_set`, `round_started`, `gate_blocked`, `stop_blocked`); a bad event exits 2 and nothing is written. Envelope and tags are documented in `docs/ledger.md`.
- `anneal eval routing [--skills DIR] [--fixtures DIR]`: Tier 1 lexical routing. Each model-invoked skill has `evals/routing/<skill>.yaml` with 8 to 10 positive and 8 to 10 near-miss prompts (a restricted YAML subset, schema in `evals/README.md`); prompts are scored by word overlap and the bar is 100% rank-1. The envelope carries a confusion table (expected skill by top-ranked skill); exit 1 on any miss, 2 on an invalid or missing fixture. `cargo test` enforces the bar over `plugin/skills`, checks that a `lint skills --cache` run reports what a fresh run does, and checks that `plugin/` holds no `evals/`.
- Hooks: `plugin/hooks/hooks.json` declares the `bootstrap` hook (SessionStart, `startup|clear|compact|resume`) in exec form with `onFailure` and a timeout, and `hooks.metadata.json` describes it (id, event, matcher, fingerprint, failure policy, role, model generation, source) against `hooks.metadata.schema.json`, all checked by `cargo test` (`docs/hooks.md`).
- `anneal hook bootstrap`: injects the bootstrap index (what anneal is, the seven entry skills with triggers, the user-invoked commands; 200 words or fewer, also in `docs/bootstrap-index.md`) at every session start, then the ledger tail only when it changed for the session. It always fails open; with no binary, the launchers print an install hint instead.
- `anneal hook guard`: a fail-closed `PreToolUse` hook on Bash (`onFailure: "block"`, 5 s timeout). It lexes the command the way a shell does, so quoting, chains, subshells, substitutions, `case`, functions, brace expansion, `bash -c`, `eval`, scripts piped or heredoc'd into a shell, variables set earlier in the command, `cd`, env prefixes, abbreviated long options (`--forc`), wrappers such as `sudo`, `xargs` and `find -exec`, and the arguments of programs it does not know (`caffeinate rm -rf /`) cannot hide a command; protected paths match in any letter case; a form it does not model is denied rather than guessed. It denies force pushes to `main`, `master` and `release/*` (or with no explicit destination), `rm -rf` outside the temporary and scratch directories, `git add -f`, and Bash writes to lint or hook config. A denial is Claude Code's deny decision with one `ERROR <reason>` line, plus a `gate_blocked` ledger event. Unreadable input or commands are denied, the deny arrives within the hook's timeout even when git or the ledger is stuck, and an unwritable decision exits 2. Allowed commands produce no output. `docs/guard.md` documents the denylist and the extension point for Clef D1.
- `anneal lint terms [--glossary CONTEXT.md] <files>`: finds the glossary's avoided terms (`_Avoid_: term, term` lines) in files as whole words in any letter case, multi-word terms included, and reports `{file, line, term}` hits; exit 1 on any hit. Files over 1 MiB are listed as skipped. Define-phase library helpers: ADR numbering (`docs/adr/NNNN-<slug>.md`, next free number, idempotent, ordered by number then slug) and the out-of-scope ruling store (`.out-of-scope/<slug>.md` with `id`, `ruled_at`, `summary` and optional `weigh_in_ref`, listed by id). Formats are documented in `docs/define.md`.
- `anneal dag check|frontier`: `check` exits 1 on a cycle (naming one cycle's ids in order) and 2 on references to missing tickets (naming each ticket and missing id; dangling wins when both occur). `frontier` lists the ready tickets (open, every blocker done) in a stable id order, each with a token estimate (body characters / 4 plus each named file's size / 4, or 2,000 when it cannot be sized), and flags those over `--budget` (default 100,000). Tickets come from local markdown (`--dir tickets`, `*.md` with `blocked_by:`/`status:` frontmatter) or, read-only, from GitHub Issues through `gh api` (`--tracker github --repo owner/name [--issue N]`: sub-issues, `Blocked by #n` in bodies). A GitHub blocker outside the issues read (an earlier release's story, a pull request) is looked up: closed satisfies it, open holds its dependant back and is listed under `external_blockers`, and only one GitHub does not find is dangling. The tracker adapter trait for ADO and Jira is documented in `docs/dag.md`.
- `anneal grill frontier --tree <file>`: validates a design tree (`plugin/playbooks/schemas/design-tree.schema.json`; cycles, dangling dependencies, duplicate ids and out-of-range probabilities exit 1) and lists the open questions whose dependencies are all answered, split into ask and look-up, with the confidence trend and the restate gate. `anneal grill confirm --tree <file> --quote <words>` appends `grill_confirmed` with the tree's SHA-256 and the human's words; a missing or blank quote is a usage error and an open question exits 3, appending nothing. The ledger registry is now version 2 (`grill_confirmed` gains optional `hash` and `quote`). The `grill` skill that drives these lands with the `spec` and `plan` skills (#20). See `docs/grill.md`.
- `anneal lint spec <file> [--glossary CONTEXT.md] [--constitution constitution.md]` and the spec template (`plugin/playbooks/spec.template.md`): checks that the required sections (Problem, Users, Requirements, Acceptance criteria, Out of Scope, Open questions, Constitution check) are present, that every acceptance criterion parses as EARS (`WHEN`, `WHILE`, `IF … THEN`, `WHERE`, ubiquitous and combined forms; a failing one gets the closest template as its fix), that Out of Scope is not empty, that there are at most 3 `[NEEDS CLARIFICATION]` markers (the count is always in `data.needs_clarification`), that the constitution check names `constitution.md`'s version, covers every gate and justifies each violated gate in a complexity table, and that no avoided glossary term is used. Exit 1 on any finding; the glossary and constitution are optional when absent. Rules, grammar and the constitution format are in `docs/spec.md`.
- `anneal lint plan <file>`, `anneal plan approve <file>` and `anneal plan check <file>`, with the plan template (`plugin/playbooks/plan.template.md`) and its schema (`plugin/playbooks/schemas/plan.schema.json`). `lint plan` checks the spec link, the Goal, Tasks and Review focus sections, `### <id>: <title>` tasks each with `Files:`, one `Test:` command and `Blocked by:`, and that every blocker is another task with no cycle (exit 1 on any finding). `plan approve` refuses (exit 3, nothing recorded) while the plan fails its lint or its spec has any `[NEEDS CLARIFICATION]` marker, and otherwise records `plan_approved` with the `sha256:` hash of the plan. `plan check` exits 0 when the plan is approved and unchanged, 3 when it was never approved, and 4 when it changed since approval; it never creates a ledger. See `docs/plan.md`.
- The first skills: `grill` (question a new or vague request in rounds until the human confirms it), `spec` (write the spec from the confirmed requirements) and `plan` (split the spec into tracer-bullet tasks with blockers, with `references/slice.md`, and get the plan approved), each with its Tier 1 routing fixture.
- A recorded dry run of the define chain (`evals/fixtures/dry-run/`): one small idea, adding `--json` to a toy CLI, taken through `grill`, `spec`, `plan` and markdown tickets, with its artifacts and ledger events. `cargo test` replays it on every commit (grill frontier and confirm, `lint spec`, `lint plan`, `plan approve` and `check`, `dag check` and `frontier`, and the recorded events and hashes), and its README lists the friction found as candidate checks.
- `anneal task done <id> [--timeout <secs>] -- <test command>`: runs the test command (no shell, its output on stderr, 30 minutes by default) and records `test_run` with the command, exit code and duration; only on exit 0 does it also record `task_done`. A failing or timed-out run records only the red `test_run` and exits 1; a command that cannot start records nothing and exits 2. The ledger registry is now version 3 (`test_run` gains optional `exit`, `duration_ms` and `timeout_secs`). See `docs/task.md`.
- `anneal floor-guard [--base <ref>]`: checks the diff against the merge base with `origin/main` (else `main`), untracked files included, for lowered quality floors: added suppressions (`#[allow(`, `#[ignore]`, `eslint-disable`, `# noqa`, `.skip(`, `xit(`), deleted or emptied test files, more tests removed than added, and lowered coverage floors, raised timeouts and loosened `*ratchet*.json` values. Exit 1 lists each hit with file, line and category; exit 2 (one `ERROR` line) when it is not in a repository, the base does not resolve, or git fails, so a check that did not run never reads as 0. It runs alongside temper's escape-hatch scan; `docs/floor-guard.md` describes the split.
- `anneal mode build --plan <plan> --tree <tree>`, `anneal mode diagnose` and `anneal mode off` record a worktree's anneal mode as a `mode_set` event (the ledger registry is now version 4), with whether the tree was clean (untracked files included). `anneal hook preconditions`, a fail-closed `PreToolUse` hook on `Edit|Write` (`onFailure: "block"`, 5 s timeout), then denies source edits in build mode until the plan's spec passes `lint spec`, the design tree is confirmed at its current hash, the tree was clean at entry and the plan is approved and current, and in diagnose mode until a `repro_red` is recorded after entry. The edit is judged by the edited file's own worktree, found from the file rather than the session's directory. Test files (including `tests.rs`/`test.rs`), the plan and tree, `.temper/`, `.anneal/`, `tmp/`, `scratch/`, `*.md`/`*.txt`/`*.rst` and files in no git repository are always allowed. `anneal mode` has no `--store`: it writes to the ledger the hook reads. A denial is one `ERROR` line naming the missing precondition and the command that satisfies it, plus a `gate_blocked` event; with no mode the hook is silent and never creates a ledger. See `docs/preconditions.md`.
- `anneal repro record [--id <id>] [--timeout <secs>] [--session <id>] -- <command>`: runs a reproduction as `task done` runs a test command (no shell, output on stderr, 30 minutes by default) and appends `repro_red`, tagged with the worktree, only when it exits non-zero (exit 0). A command that exits 0 records nothing and exits 3; one that times out records nothing and exits 4 (a hang is not a reproduction); one that cannot start exits 2. The preconditions hook now counts only `repro_red` events tagged with the edited worktree, so a reproduction in a sibling worktree, or one appended by hand without a worktree, no longer unlocks diagnose mode. `anneal repro leftovers` lists each line holding a `[DEBUG-<id>]` tag in the files git knows of (tracked and untracked, not ignored) as `file:line` and exits 1 when there is one; it reads at most 1 MiB per file and 64 MiB in all, listing what it did not read under `skipped` (and `over_budget` when the total ran out). See `docs/preconditions.md`.
- The `diagnose` skill: reproduce a failure red with `anneal repro record`, rank falsifiable hypotheses, test them one at a time with `[DEBUG-<id>]`-tagged instrumentation, fix the cause and clear the leftovers. Its routing fixture is `evals/routing/diagnose.yaml`.
- Ratchets: `.anneal/ratchets.json` (`{"version": 1, "ratchets": {"<name>": {"value": <number>, "direction": "down"|"up"}}}`) holds numeric floors that may only move the good way. `anneal floor-guard` reads it strictly and reports a ratchet that moved the wrong way since the merge base, was removed or changed direction, or a file that no longer parses, as `ratchet_loosened`; the generic `*ratchet*.json` rule stays for other tools' files and skips this one. See `docs/floor-guard.md`.
- `anneal hook fast-check`, a fail-open `PostToolBatch` hook (15 s timeout): once per batch of edits, in an anneal mode, it runs `anneal floor-guard`, the repository's `check_fast` command from `.anneal/config.json` (argv, no shell, 5 s), the glossary's avoided terms on the changed files, and `lint spec`/`lint plan` on changed specs and plans. A lowered floor blocks with one `ERROR` line; every other failure is a note; it is silent when everything passes. See `docs/hooks.md`.
- The `build` skill: builds an approved task test-first, entering build mode with `anneal mode build`, completing through `anneal task done`, and running `temper:gate` at task boundaries in Rust repositories; `references/constraints.md` (the `CONSTRAINTS.md` format and check placement by cost) and `references/tdd.md`, with its Tier 1 routing fixture. `plan` and `diagnose` now name `build` as a sibling, and `grill`'s trigger mentions a new idea.
- `anneal hook completeness`, a fail-open `Stop` hook (30 s timeout): blocks a reply that claims success ("done", "all tests passed", "fixed", "complete" and the rest of a documented list, in their inflections, as whole words outside code, unless negated in the same clause) while a source file changed after the worktree's latest green `test_run` started, and blocks on any `[DEBUG-<id>]` leftover; the active playbook's missing events (build: a green run after entry once source changed; diagnose: a `repro_red`) are context, never a block. It blocks at most 2 times in a row per session (counted in `~/.anneal/stop-blocks.json`, reset by a tool call or a clean stop), does nothing when `stop_hook_active` is set, records each block as `stop_blocked`, and reports its own failures as one `ERROR` line. `anneal task done` now tags its events with the worktree, so only this worktree's runs count. See `docs/hooks.md`.
- `anneal hook status`, a fail-open `SubagentStop` hook (15 s timeout): records each subagent's status block (`Status:` DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT or BLOCKED, then Gate, Review, Changed, Decisions needed and Not verified) as a new `subagent_status` event, with its duration and token use read from its transcript; a missing or malformed block is recorded as a violation. The ledger registry is now version 5 (`subagent_status`, tag key `agent:`).
- The `verify` skill: before calling work done, run the tests fresh with `anneal task done`, run `temper:gate` in a Rust repository, clear `[DEBUG-` leftovers, and run a doubt pass (reviewers get the artifact and the contract, never the claim; findings without `file:line` are rejected; at most 3 cycles). It stops at the local pass. Its routing fixture is `evals/routing/verify.yaml`.
- `anneal decide --point <D1..D7> --question <noul|choice|score> --state <json> [--option <o>]...`: the Clef client every decision point will share. It routes D4 to `clef` and the other points to `clef-flash` (model ids in `plugin/playbooks/clef-thresholds.json`, with the blueprint's thresholds), applies the point's bands to the probability Clef returns (never to its `confidence`), and appends one row per call to `~/.anneal/decisions/decisions.jsonl` (outside the plugin's directories, so it survives a reinstall; rows capped at 8 KiB, the file rotated at 16 MiB keeping four old files). `clef_mode` is `off`, `shadow` or `enforce` with per-point overrides (`shadow,D1=off`), and a point stays in shadow for its first 50 answered decisions. Exit 0 with the action, 3 when Clef is off (no account, or mode `off`; nothing logged), 5 when Clef gives no answer within 2 s (the row records `unreachable`, and the envelope names the fallback: `ask` for D1, fail open for the others) or the account, token or mode is malformed (the envelope names the variable; nothing is logged). Choice options are 1 to 64 of `A-Z a-z 0-9 _ . : -`, and probabilities that do not sum to 1 within 0.05 count as a bad response. `anneal decide label <id> <outcome>` appends an outcome row. The token never appears in output, errors or the log. No HTTP client is bundled yet (a pending dependency decision), so every call currently exits 5. See `docs/decide.md`.
- `anneal calibrate [--point <D1..D7>] [--thresholds <file>]`: reads the decision log, rotated files included, and joins each answered decision to its latest `decide label`. For every point it reports n, the labelled n, the Brier score, 10 reliability bins with their observed frequency, the ask rate, and the threshold of the lowest band that minimises expected cost on the labelled set (a false accept costs 5, a needless intervention 1), proposed only when strictly cheaper than the current one. Each point gets a verdict: `stay-shadow` with fewer than 50 labelled decisions, a Brier score over 0.15 or an ask rate of 20% or more, else `eligible-to-enforce`; a question whose rule has no bands, such as D3's size, only records and never holds its point back. It writes every point's proposal to `~/.anneal/decisions/proposals.json` and lists the manual edits that would apply it (the thresholds file's JSON pointer and value, and the `clef_mode` override); it never applies them. The envelope goes to stdout, a short best-effort summary to stderr. Labels come only from `decide label` for now. See `docs/calibrate.md`.
- Clef D1 in `anneal hook guard`: after the denylist, a Bash command it did not deny is asked of Clef (`noul destructive_or_irreversible`) in process, sharing `decide`'s thresholds, modes, shadow period and decision log. In enforce mode 0.90 or more denies (rule `destructive`, with a `gate_blocked` event), 0.40 or more asks the human, and less defers; when Clef gives no answer, or D1 is set to enforce but cannot run (its anneal home, thresholds, counts or clock), the guard asks; an answer that cannot be logged keeps its deny or ask (a defer asks), so a log failure never lets a command through, and a Clef failure never denies. In shadow mode (the default) the would-be action is only logged and the verdict is unchanged; with Clef off nothing is asked. The command Clef gets and the row keeps (a new `input` field) is trimmed, cut to 1,024 characters and redacted wherever they appear, inside quotes and `bash -c` bodies too: the value of every `NAME=value` whose name looks like an environment variable (`FOO=bar`, `K[0]=v`, `K=(a b)`) or holds a credential word in any case (`api_token=x`), credential flag values (`--token=…`, `--password …`), comments and heredoc bodies become `<redacted>`, lowercase operands such as `dd of=` are kept, and anything after an unclosed quote or substitution is redacted. A deny after a slow Clef call skips the ledger record rather than overrun the hook's timeout, and says so. With no HTTP client yet every call is unreachable, so D1 stays in shadow and nothing changes for users. Automatic outcome labels (approve or deny on an ask, a revert within 24 h) are a follow-up. See `docs/guard.md`.
- `anneal hook route` and `anneal hook ruled-before`, two fail-open `UserPromptSubmit` hooks (5 s timeout each) that ask Clef about every prompt through `decide`'s own code, so the thresholds, the log, the mode and the 50-decision shadow period are the command's. `route` (D3) asks the phase (a choice over the 8 phases of `plugin/playbooks/route.json`) and the size (a score read as trivial, small, medium or large) at once, within one 2 s Clef timeout (the size has no bands, so its answers are logged but, like any record-only answer, no longer count toward a point's 50-decision shadow period); at 0.60 or more, in enforce mode, it injects one line naming the phase's entry skill, the phase, the size and its depth. Each answered phase decision is labelled at the session's next prompt with the phase whose entry skill the model then invoked (one `route-pending/<hash>.json` per session beside the decision log, so parallel sessions never share a file). `ruled-before` (D6) offers the `.out-of-scope/` rulings and the accepted weigh-in decision atoms in `.kb/_intake/decisions/` (by their `wi-` id) plus `none`, at most 31 rulings (the store read within 4,096 entries and 256 files, without following symlinks); at 0.70 or more, in enforce mode, it injects one line naming the ruling and saying not to re-open it. In shadow mode, the default, both only log. Clef off means they do nothing; Clef unreachable means they log the miss and stay silent; an answer whose row could not be logged is never injected. The prompt sent is whitespace-collapsed, redacted with the guard's rules for credential assignments (`<redacted>`, a quoted value through its closing quote or to the end) plus bearer tokens and obvious token shapes, even inside punctuation, and cut to 1,024 characters; the log keeps only its hash. Each hook measures a 4.5 s budget from its start and skips Clef, with a note, when its 2 s timeout no longer fits. Their own failures are one `ERROR` line as `systemMessage`. See `docs/hooks.md`.
- `anneal grill classify --tree <file> --node <id>`: Clef D7 (`noul is_decision`) on one open question of a design tree, asked in process with `decide`'s thresholds, modes, shadow period and log; Clef gets the redacted question and goal, and the row keeps neither. Only once D7 enforces does it write Clef's probability into the node's `is_decision`, so `grill frontier`'s ask and look-up lists follow Clef; in shadow, and when Clef is off or unreachable, it only logs and the tree stays as the model wrote it (exit 0). The `grill` skill classifies each new open question and labels an asked one `no` with `anneal decide label` when the human says it could have been looked up (else `yes`). Release 4's exit check, a session that logs D1, D3, D6 and D7 and is read back by `anneal calibrate`, runs in `cargo test`. See `docs/grill.md` and `docs/decide.md`.
- Redaction before anything reaches Clef now also covers, in the guard's command and in prompts, grill questions and goals alike: an assignment whose name is quoted (`export "API_KEY"=x`, `declare -x 'PASSWORD'=x`); names holding `pass`, `auth`, `bearer` or `cookie` (`db_pass=x`; `--author=` stays readable); the value after a credential-named key anywhere in a word (`--from-literal=password=x`, `-Dpassword=x`, an npm `:_authToken=x`, `{"password":"x"}`, `pass:x`); the value of any option, one dash or two, whose name names a credential (`--password x`, `-storepass x`, `-passout x`); the value of a credential-named header, never past the end of its command (`Authorization:`, `X-Api-Key:`, `PRIVATE-TOKEN:`, `Cookie:`, a quoted `"Authorization":` key); the word after `Bearer` or `Basic`; the value after a credential-named configuration key (`aws_secret_access_key x`, `user.password x`), but not after a `-stdin`, `-file` or `-env` option; the `user:token@` of a URL, a `#` or a `?` in the password included; Vault `hvs.`/`hvb.` tokens and the token after `vault login`; obvious tokens in commands too; and the secret options of `mysql`/`mariadb` (`-pX`), `curl` (`-u`, `-U`, `-b`, `--user`, `--proxy-user`), `sshpass` and the MongoDB tools (`-p`), `redis-cli` (`-a`), `sqlcmd`/`bcp` (`-P`), the LDAP clients (`-w`), `smbclient` (`-U`), `docker`/`podman`/`nerdctl`/`helm login` (`-p`), `twine` and `az login` (`-p`) and `gh secret` (`--body`), also when the program or option is quoted (`"mysql"`, `'-pX'`). In prompts, a quote opened in the middle of a value (`TOKEN=abc"def ghi"`) or by a secret value (`-u "me:my pass"`) is redacted through its close. See `docs/guard.md` and `docs/hooks.md`.
