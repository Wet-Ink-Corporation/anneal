# Changelog

All notable changes to anneal are recorded here. A release renames `## Unreleased` to `## <version> — <date>`; that section is the release notes.

## Unreleased

- Guard: a glob or extended glob where a shell or wrapper reads its options is judged as an option it may expand to, since a file named `-c` in the directory turns `bash -[c] 'rm -rf /'` into `bash -c 'rm -rf /'`. Such a word (`-[c]`, `-@(c)`, `?c`, `@(--)login`, `+[c]` for a shell, or one with a value attached such as `env -S@(rm -rf ~)` or `env -[S]'rm -rf ${HOME}'`) is read both as before and as an option that cannot be known, which denies: `bash -[c] 'rm -rf /'`, `su -@(c) …`, `sudo -@(s) …`, `env -@(S) …`, `flock /tmp/l -@(c) …` and `su root -- -[c] …` are denied, while `bash run.sh *`, `bash *.sh`, `sh -c '…' *` and `sudo rm -f *.o` are allowed as before. Variables in those places stay the documented word-splitting limit (#165).
- `anneal eval uplift` (Tier 3): a case may name a fixture (`"fixture": "<name>"`, the directory `evals/uplift/fixtures/<name>/`), so its runs no longer start in an empty directory. Each run copies the fixture into its workspace (symlinks dereferenced, so a fixture may link to the repository's `docs/`) and commits it as a fresh git repository, through a `claude plugin eval` scaffold script (`case.yaml` at schema 1.1). A scaffold runs outside the eval sandbox with your rights, so a run whose selected cases name a fixture is refused (exit 2) unless `--allow-scaffolds` is given, as gated tools need `--allow-gated-tools`; `--check` lists those cases in `data.scaffolded` and an `eval/uplift/scaffolded` finding. A fixture name that is not plain (a path separator, `..`), a missing or empty fixture, and a fixture symlink that dangles or leads out of the repository are case problems. Every plugin copy a run makes now carries the running `anneal` at `libexec/<target>/anneal`, the launcher's first choice on this host (`data.libexec_target`), since the launcher's release download fails inside the eval sandbox; on a host the launcher does not know, none is placed and an `eval/uplift/libexec` finding says so (#44).
- Guard: an `env -S` string is no longer read with extended glob groups, which env does not know, so `env -S '@(rm -rf ~)'` is denied again as `rm -rf ~`; it is read as shell text too, so `env -S rm @(-rf) /home` and `env -S 'watch rm @(-rf) /home'` stay denied. It is also read as env splits it, each word after the string kept whole and env's escapes (`\_`, `\t` and the other control escapes, `\c`, `#`) applied and shell operators and backticks read as the characters env takes them for, so `env -S bash -c 'rm -rf /'`, `env -S 'bash -c #' 'rm -rf /'` `env -S 'rm\_-rf\_/'` `env -S 'rm -rf ; /home'` and `env -S '-S "rm -rf /"'` (env reads its split words as its own options), allowed before, are denied. An option word that is itself a pattern (`env -S@(rm -rf ~)`) is a documented limit (#147).
- Fixed: a call that feeds a child its input (the weigh-in bridge) is no longer a timeout when the child exits normally but leaves a process holding its stdin unread: once the child exits only its output is waited for. A `gh` timeout is named as the limit it was given (`500ms`, `30s`), as git's is (#153).
- Fixed: a `Tree:` or `Spec:` line whose markdown link puts its destination in angle brackets (`Tree: [t](<../trees/t.json>)`, CommonMark's form for a path with spaces or parentheses) now names the path inside them. A `Tree:` link of that form was read as the template's `<placeholder>`, so `anneal plan approve` refused it as naming no design tree and `anneal lint spec` did not check it; a `Spec:` link of that form named `<...>`, brackets included. A bare `<placeholder>` value is still a placeholder (#152).
- Added: `anneal decide label <id> <outcome>` takes `--actor human|model` and `--via mod|bash|terminal` and records them on the label row in `decisions.jsonl` (`"actor"`, `"via"`); without them the row is exactly as before and claims no source. `anneal calibrate` counts, per point and question, the labelled decisions whose last label came `via: mod` (`labelled_via_mod` in the envelope and `proposals.json`; `via mod N` in the stderr line, shown only when N is above 0). Labelling an id again keeps both rows, and calibrate uses the last. Old label rows, and a `via` this build does not know, still read. This is the CLI half of #61; the buttons land with the cockpit mod.

- Guard: extended globs (`shopt -s extglob`) are read as globs. `@( )`, `+( )`, `!( )`, `?( )` and `*( )` make one pattern word, so `rm @(-rf) /home`, `rm +(-)rf /home` and `rm !(x) /home` are denied as operands that may match a file named `-rf`, and `tee .clau?(de)/settings.json` or `echo x > .clau@(de)/settings.json` as writes that may reach protected config; `rm -f @(a|b).o x` stays allowed, and `!(...)` in command position is still the `!` keyword and a subshell whose commands are checked. A `<( )` or `>( )` inside a group is denied as unparseable, as bash may end the group inside it. So is a backtick or a `$[ ]` inside a group, which bash reads differently there. A word ending in an opener before an empty `()` where a function's name may stand (`f?() { ...; }`, `/bin/rm@() -rf ~`) is denied as unparseable, since bash reads it as a definition without extglob and as a pattern program with it; a group in a program word (`/bin/r@(m) -rf ~`) is judged as an unknown program. Word splitting of an unquoted expansion or `"$@"` (including an empty one that vanishes) and a force flag held in `git push "$branch"` are now documented limits in `docs/guard.md` rather than open gaps (#128, #127).
- Added: a spec names the design tree it was written from with a `Tree:` line under its title (`plugin/playbooks/spec.template.md`), read as a plan's `Spec:` line is, relative to the spec. `anneal lint spec` checks it with a new rule, `tree`: one such line, naming a file that is a valid design tree, reported as `data.tree`. `anneal plan approve` then refuses (exit 3, nothing appended, no ledger created) until one of the latest 256 `grill_confirmed` events carries that tree's current hash, so a spec whose tree was never confirmed, or was edited after its confirmation, cannot have its plan approved (`plan/approve/unconfirmed-tree:<tree>`); a `Tree:` line naming no file, or still the template's placeholder, is refused too (`plan/approve/tree:<spec>`). A spec with no `Tree:` line lints and approves as before. See `docs/spec.md` and `docs/plan.md` (#77).
- Fixed: a git timeout is named as the limit git was given (`git did not answer within 500ms`, `1s`, `1.5s`) rather than in whole seconds, which showed the preconditions hook's sub-second budget as `0s`. And a child process that leaves a process holding its output pipe (a `git` wrapper script running `sleep 30`) no longer holds the call until that process exits: every call anneal makes to `git`, `gh` and `weighin` returns at its timeout plus about 100 ms. Only the child itself is killed; a descendant holding the pipe lives on until it exits, and anneal stops reading from it (#132).
- Fixed, completeness (Stop) hook: an irregular past verb (`ran`, `hit`, `got`, `broke`, `took`, `went`, `came`, `made`, `built`, `found`, `saw`, `threw`, `fell`, `left`, `lost`, `sent`, `said`, `began`, `wrote`) now finishes a conditional's scope as an `-ed` verb does, so "The crash when the parser hit EOF is fixed", "The flake that appeared when CI ran is fixed", "The bug when the cache got cold is resolved" and "When I ran it all tests pass" block, as they did before #84; so does a plan whose condition holds one ("If the build went green I'll merge."), an accepted false positive. No reply that blocked before stops blocking: plans after a clause-opening `after` or `before` ("After the tests pass, I'll open the PR.") still block, an accepted false positive (#135).
- `anneal status [--json] [--fields a,b] [--tail N]`: one read model for every UI. It folds the ledger and the anneal home into one versioned document (`schema: 1`; fields are only ever added within it): the worktree's mode and playbook, the build plan's approval (approved, stale or none, with its hash and when), its tasks done and in all, the newest gates that blocked (`gate_blocked`, `stop_blocked`, with their ledger positions), the verdict for `HEAD` and whether it is still fresh (by commit, or by patch id after a rebase), each Clef point's answered decisions and mode, the latest context-usage snapshot and the ledger's newest events. A section with no data is absent; one that cannot be read is absent with a `status/unreadable:<section>` finding. `--fields` limits the work to the sections named; the text form is at most 12 lines. Exit 0, or 2 when no ledger exists (it never creates one). See `docs/status.md` (#58).
- Added: `anneal snapshot write --json` saves a context-usage snapshot read on stdin (`session_id`, `window`, and `used_tokens` or `used_percentage`; optionally `window_source`, so a saved snapshot round-trips) to `~/.anneal/context-usage-mod.json`, beside the status line's `context-usage.json` and in its format, so the TypeScript mod can feed the context monitor without the user wiring a status line. Input of another shape or out of range exits 2 with one `ERROR` line and saves nothing. Every snapshot now records its `source` (`mod` or `statusline`) and `written_at_ms`; an older snapshot reads as the status line's. When both sources hold a reading for the session, the context monitor judges the fresher (the mod's on a tie), at the same 60% and 75% thresholds, once per crossing. The session start's one-time status-line hint stays away while a mod snapshot is under 10 minutes old. `anneal statusline` behaves as before. An anneal older than this refuses the new fields, so its context monitor reports one `ERROR` line until it is updated (#60: CLI half; the mod lands with #57).
- Guard: wrapper options are read as each wrapper's getopt reads them, checked against the real binaries (`crates/anneal-cli/tests/fixtures/wrappers/probes.txt`). Commands that ran `rm -rf /` past the denylist are now denied: a short-option cluster ending in a value letter (`sudo -iu echo rm -rf /`, `env -iu echo …`, `ionice -tc echo …`, `xargs -tn echo …`), value letters only some implementations have (`sudo -R`, `-c`, `-a`, OpenBSD `doas -a`, BSD `env -P`/`-L`/`-U`, BSD `xargs -J`/`-R`/`-S`), `chrt` without a numeric priority (`chrt -o rm -rf /`, which util-linux 2.42 runs), and a later `-c` of `su` or `script` (`su -c ls -c 'rm -rf /'`; both run the last one, and every one is now read, each on its own so that an earlier one ending in `\` or opening a here-document cannot hide the next). Optional letters (`xargs -e`, `-i`, `-l`, `watch -d`, `script -t`) take only the rest of their cluster, so `xargs -eE rm -rf /` stays denied and `script -tqc x rm -rf /` stays allowed. `sudo -h` takes the next word as a host (sudo runs the command on the local host). `su`'s words after the user, which it hands to the user's shell, are read as the shell reads them, with and without `POSIXLY_CORRECT` (`su root -- -c 'rm -rf /'`, `su root -- -c -x 'rm -rf /'`, `su - -- root -c 'rm -rf /'`; an operand after su's value options, such as `su root -w PATH <(curl …)`, is the shell's script file; bash's own options are read as bash reads them, so `bash -ox pipefail -c …`, `bash -rcfile x -c …`, `bash +c …` and `su -c -x root 'rm -rf /'` are read too). Options newer than the probed binaries take their values too (`env -a`, `watch -s`, `chrt -U`/`-X`), and FreeBSD `env --C` is read as `-C`. `env -` and su's `--session-command` are read too. In the merge gate, `env -vu X -C /tmp gh pr merge …` is now denied as `directory` (env's `-C`) rather than `shape`. Costs: every shell is also read without bash's long options (a name does not say which shell runs), so `git log | bash --version` is now denied and a body after a bash long option (`bash --login -c …`) is hidden from Clef (#121).
- `anneal dag frontier`'s token estimate: a ticket that lists `files:` is now sized by those files alone, so a path its body mentions for context (`` `plan.md` ``) no longer adds to it. A ticket with no `files:`, such as every GitHub issue, still counts the backticked paths in its body (#68).
- Store resolution: git 2.56's "gitfile does not point to a valid repository" counts as outside git, as older git's "not a git repository" did for the same `.git` file pointing nowhere, so such a directory uses `<folder>/.anneal` on every git version instead of failing with "git failed in …" (exit 70).
- Install: a plugin that carries no binaries (synced from claude.ai into cloud sessions, or installed from a marketplace that serves `main`) no longer leaves every guard blocking every Bash, Edit, Write and Agent call. After `libexec/` and PATH, the sh launcher now runs the release build for the plugin's version, downloaded once from the GitHub release (`anneal-<target>`, kept only when it matches the release's `SHA256SUMS`) and cached in `~/.cache/anneal/<version>/<target>/` (`$XDG_CACHE_HOME/anneal` or `$ANNEAL_CACHE_DIR`). Each try fits its hook's timeout, resumes a partial download, and is not repeated for 2 minutes after a failure; `ANNEAL_NO_FETCH=1` turns it off. When no build can be found or downloaded, anneal is off for the session instead: the guards exit 0 like every other hook rather than blocking every Bash, Edit, Write and Agent call, and the session-start warning says so and why. A guard whose binary runs and fails still blocks. The Windows launcher does not download yet. The README's install section now covers cloud sessions.
- Completeness (Stop) hook: more success claims are caught after an untested edit. Besides the phrases ("Everything works.", "It's working", "The feature is implemented", "Ready to merge.", "Ready for review", "Resolved.", "All checks pass."; `check`, `build` and `lint` join `test` before `pass`), up to two filler words may stand between a claim's words ("The tests now pass.", "Everything is still working.", "All the tests pass"; `the` and `both` only before the suite, so "Test the pass rate" does not block), suites may be joined ("Tests and lint and builds pass."), and a hyphenated word counts when it spells a claim ("all-green", "ready-to-merge", "unit-tests pass"). A bracket, `so` and `but` end a clause, so "Done (anything else?)" and "All tests pass so should I merge?" still block. Some replies that blocked before no longer do: a claim inside a question ("Did the tests pass?"), a claim inside a conditional's scope (`if`, `once`, `when`, `whenever`, `unless`, `until`, and `after` or `before` when they do not open the clause; the scope ends at the next `and`, `then` or `now`, a second `is`/`are`/`was`/`were`, the condition's own past-tense verb or the clause end), so "I'll merge once the CI checks pass." and "Wait until all the tests pass" no longer block, while "I re-ran the suite after the rebase and all tests pass.", "Once the fix landed all tests pass", "The crash when saving is fixed.", "The panic when the file is empty is resolved." and "I ran it once more and all tests pass." still block, as does "Merge when lint is clean and all tests pass". A "works" claim after a purpose word ("run the tests to make sure everything works", "I still need to get it working", "Let me know whether it works") no longer blocks, and a hyphen inside a word no longer ends a clause, so "It's half-done, not finished." no longer blocks; a spaced hyphen, `--` and dashes still do (#84).
- Route hook: past 64 sessions with a pending phase decision, dropping the oldest no longer deletes a decision another prompt's hook is labelling (which made that hook report an `ERROR` line); claimed decisions are kept apart, at most 64 of them (left only by a hook killed while labelling), and one found gone is simply not labelled (#91).
- `anneal dag check --plan <plan.md>` checks that the tickets agree with the plan: a ticket answers the task of the same id (a markdown ticket's file stem), and a task with no ticket, a ticket with no task, or a ticket whose blockers among the plan's tasks differ from the task's `Blocked by:` is a finding (`dag/plan/no-ticket`, `dag/plan/no-task`, `dag/plan/blockers`; a plan `lint plan` cannot fully read, or whose tasks name a blocker outside the plan, is `dag/plan/unread`). A blocker from outside the plan is never a disagreement: a ticket that is no task but blocks a task's ticket, directly or through other such tickets (a `tickets/REL-5.md`), is not reported. A ticket's blockers count through outside tickets too: a ticket blocked by `R1`, itself blocked by task `T1`, must name `T1` in the plan. With GitHub, pass `--issue`, or every unrelated issue, open or closed, is a ticket with no task. At most 1,000 disagreements are listed, the rest counted in `data.plan.omitted`. It exits 3 when the graph passes but the tickets disagree, keeps 1 and 2 for a cycle and a dangling blocker, and lists the comparison in `data.plan`. Without `--plan`, `dag check` is unchanged. See `docs/dag.md` (#75).
- `anneal plan check` says what it compares: its `--help`, the green-result claim and the exit-4 meaning (`stale: the plan's bytes changed since approval`) now state that only the plan's bytes are compared with its latest approval, not its spec, as `docs/plan.md` documents. Behaviour is unchanged (#76).
- The preconditions hook now gates `MultiEdit` (its `file_path` and any edit's `file_path`) and `NotebookEdit` (`notebook_path`) as it gates Edit and Write, and `hooks.json` matches `Edit|Write|MultiEdit|NotebookEdit`; a call naming more than 16 files is denied as bad input. A path is judged where the OS writes it: a symlink followed by `..` climbs from the link's target, and a write through a dangling symlink is judged at the file it creates (at most 40 links, else denied), so `tmp/link/../app.py` with `tmp/link -> ../src/deep` is source. Where a tool may take `..` lexically before the OS sees the path, that reading is judged too and either's denial denies: with `src/link -> ../tmp/sub`, `src/link/../x.py` is judged as `src/x.py` as well as `tmp/x.py`, so it is denied wherever `src/x.py` is. Each worktree a call reaches is found and read once, and the whole call is judged within 3.5 s of the hook's start; past that the edit is denied (`unjudged`). A symlink in another repository leading into a gated worktree is judged by that worktree's mode. The `repro_red` worktree scoping #80 also asked for was already in place since #25 (#80).
- The guard judges what an `rm` operand could expand to: one whose first part may be a `-` (a variable or substitution, or an unquoted `?`, `*` or bracket expression that may match a file named `-rf`) followed only by letters, digits and `-` may hold `-rf`, so `rm "$b"rf /home/x` and `rm "$a"{r,f} /home` (with `b` or `a` set to `-`), `rm ?rf /` and `rm "$b"[-]rf /` are now denied. New costs: `rm "$p"old "$p"new` and `rm -f * x` are denied (write `--` before such operands); `rm "$f".txt "$g".txt`, `rm -f "$tmpdir"/x` and `rm -f *.o *.a` are still allowed. A `]` inside an expansion in a bracket expression does not close it (`rm [!$(echo ])]rf /home` is denied), and a `[:`, `[=` or `[.` that never closes is a member of a set that closes at the next `]` and may match `-` (`rm [[:-]rf /home` is denied; a cost: `rm -f [[:a]x /home` too). Only the operand as one word is judged: word splitting of an unquoted expansion or `"$@"` into a separate `-rf` (`rm x$b /home/x`, `set -- a -rf; rm x"$@" /home/x`) and extended globs (`rm @(-rf) /home`) are known gaps, listed in `docs/guard.md` (#128). A command holding a brace group is now read brace-expanded, as the shell expands it before any program, wrapper or shell reads its options: `bash {-c,'rm -rf /'}`, `caffeinate {bash,-c,'rm -rf /'}`, `caffeinate {env,-S,'rm -rf /'}`, `caffeinate {sudo,-u,root,rm,-rf,/}` and `caffeinate {rm,-rf,/}` were allowed (or denied for the wrong reason) and are denied as what they run, while `brew install {git,jq}` stays allowed. Brace expansion now reads quotes as bash does: a quoted or escaped `{`, `,` or `}` is no part of a group, and neither is a variable's value or xargs input, so `bash {-c,'echo ,; rm -rf /'}` and `caffeinate bash -c 'rm -rf {/tmp/x,/}'{,}` are denied, and `x='{-rf,/}'; rm $x` and `echo '{-rf,/}' | xargs rm` are allowed, as they remove a file named `{-rf,/}`; an empty unquoted product is no word, so `echo 'rm -rf /' | bash {,}` is denied as the stdin script it runs. A product with no variable or substitution left in it is read as written even when another product of its word kept one, so `git push {-f,origin$x}` (denied before #127 too) and `bash {-c,"rm -rf /$x"}` are denied; the 256-word cap counts only the words brace expansion makes, so `echo` followed by 256 of them is allowed again. The merge gate reads a gh operand brace expansion made as written, so `caffeinate {gh,pr,view,1}` stays allowed and `bash {-c,'echo ,; gh pr merge 1'}` is gated (#127).
- `anneal lint plan` lists at most the first 1,000 tasks in `data.plan.tasks`; `data.tasks` still counts every task read, and the new `data.omitted_tasks` (present only when some were left out) counts the rest, so a 1 MiB plan of unique tasks no longer gives a ~6 MB envelope. `anneal grill`'s design-tree check now names a `depends_on` cycle with the same depth-first search as `anneal dag check` (one shared detector); a tree with several cycles may name a different one than before.
- `anneal dag frontier`'s token estimate no longer counts backticked words that are not files: globs (`` `tickets/*.md` ``), command names and absolute paths (any word starting with `/`, such as `` `/orchestrate` ``; a `files:` entry is still counted) and dotted identifiers with no `/` and no known file extension (`` `grill.confirmed` ``, `` `data.needs_clarification` ``). Paths such as `` `src/lib.rs` ``, `` `docs/dag.md` `` and `` `Cargo.toml` `` still count, and `files:` entries count as written. `docs/dag.md` lists the known extensions and notes that paths are sized relative to the working directory.
- A `clef_mode` (`CLAUDE_PLUGIN_OPTION_CLEF_MODE`) that does not parse is echoed in `decide`'s `data.reason` cut to 64 characters (with `…`), as the status hook cuts an unknown status word, rather than whole. `calibrate`'s threshold halfway above every labelled probability is rounded to 4 decimal places (`0.85`, not `0.8500000000000001`) in `proposals.json` and the apply steps when the rounded value still lies strictly between its neighbours.
- A usage error for a missing required argument now names it, for every command: `anneal lint terms` with no file says `ERROR missing required argument: <FILE>...` instead of clap's `the following required arguments were not provided:`; several missing arguments are listed comma-separated. Still exit 2 with nothing on stdout.

## 0.0.5 — 2026-10-14

- Guard redaction is now an allowlist skeleton: the Bash command sent to Clef (D1) and kept in the decision row shows only programs and wrappers (by name, without their path), keywords, option names and the separators `; ` and ` | `, with every argument value (including any word after a literal `--`) replaced by `<redacted>` unless a fixed table names it (a program's subcommands such as `push` or `delete`, no-value flags such as `-rf` and `--force`, `dd`'s `if=`/`of=`, and sensitive targets such as `/`, `~`, `.`, `*`, `HEAD`, `main`, `origin` and block devices). Assignments show `NAME=<redacted>`, the inside of an arithmetic expression (`$(( ))`, `(( ))`, `$[ ]`) is `<redacted>`, a wrapper is read as the guard's denylist reads it, and from the first wrapper option the redaction cannot read with certainty (a short-option cluster other than a shell's flags ending in `c` such as `bash -lc`, an option it does not know, a value or operand without its slot's strict shape such as `timeout x psql` or `watch -n cmd`, or one the wrapper may refuse whatever its syntax such as `xargs -n 0`, `env -u a=b` or an empty word, or not literal such as `sudo -u $U`, `env -S` or `watch -x`, which run their words without a shell, a `find` word before an action its tables cannot read, `taskset -p`, any `chrt` (its priority's range depends on the policy), `xargs -I` (it puts each input item in place of the replace string, the program included), a non-literal assignment after a wrapper such as `env K=$V`, a body option followed by another option word such as `su -c 'x' -c ls`, a body followed by words its wrapper would refuse, such as `flock /l -c 'x' y`, `script -c 'x' a b`, a shell option the shell may refuse or that changes what the body runs such as `dash -B`, `bash -l --norc`, `bash -r` or `bash -k`, `su -s`, a `find` expression that may never reach its action such as `-print -o -exec`, and always `trap`'s action, `alias`'s value and the word after `builtin`, `busybox`, `function NAME` or `coproc`, which may not run) the rest of that command is hidden as arguments (`sudo -iu postgres psql` is `sudo -<redacted> <redacted> <redacted>`), redirections keep their operator, a literal `bash -c`/`eval` body or `find -exec` action is rendered the same way, and a command the lexer cannot read is sent as `<unparsed>`. The guard's denylist is unchanged: redaction never changes what it denies. D1 sees less than before (file names, other branch names, numbers and option values are gone); `git push --force origin main`, `rm -rf /` and `terraform destroy -auto-approve` keep their signal. Prose redaction (`decide`, prompt hooks, `grill classify`) is unchanged (#89).
- `anneal eval uplift`: a refusal of the first batch now reports what that batch spent instead of nothing, and a later refusal keeps the spend marked as a lower bound, in `anneal eval routing --router claude` (Tier 2) too; `anneal lint rules` reads the default hooks metadata only when a rule names a `hook` enforcer; the guard's time budget now covers every ledger lock wait its record can meet (16 of 100 ms) instead of one 500 ms wait (#89, #108).
- `anneal watch pr` reads a `blocked` pull request again once its checks pass and no thread is open, and exits 6 only when it is still blocked at the same head, so a last check finishing between reads is much less likely to block one poll early. Finding keys in a watch envelope are unique (`watch/thread:no-comment`, a `:2` suffix for repeats), and when both the GraphQL and the proxy thread routes fail, the one `ERROR` line names both failures (exit 7) (#89).
- Injection scan: a supplementary variation selector (U+E0100..U+E01EF) on its own is now a hidden-character hit unless it follows a Han ideograph, and paths holding such characters are withheld; `docs/injection-scan.md` and `docs/watch.md` list the known gaps (#89).
- Merge gate: a merge is judged only as the canonical command, run as a Bash call of its own with every word written out: `gh pr merge <n> --match-head-commit <HEAD> --repo <host>/<owner>/<repo>`, optionally with `--squash`, `--merge`, `--rebase`, `--delete-branch`, `--auto`, `--subject` or `--body` (a text may be quoted). `--repo` must name the worktree's `origin`; gh reads it before the working directory, `GH_REPO` and `GH_HOST`. The tripwire catches mistakes and casual workarounds, not a determined adversary; interpreters, make, scripts on disk, words built at run time without `merge` or `gh`, rc-file aliases and the session's environment are not seen, and strong enforcement is a GitHub required check or branch protection (`docs/verdict.md`) (#89).

- `anneal grill frontier --tree <file>`: validates a design tree (`plugin/playbooks/schemas/design-tree.schema.json`; cycles, dangling dependencies, duplicate ids and out-of-range probabilities exit 1) and lists the open questions whose dependencies are all answered, split into ask and look-up, with the confidence trend and the restate gate. `anneal grill confirm --tree <file> --quote <words>` appends `grill_confirmed` with the tree's SHA-256 and the human's words; a missing or blank quote is a usage error and an open question exits 3, appending nothing. - `anneal lint spec <file> [--glossary CONTEXT.md] [--constitution constitution.md]` and the spec template (`plugin/playbooks/spec.template.md`): checks that the required sections (Problem, Users, Requirements, Acceptance criteria, Out of Scope, Open questions, Constitution check) are present, that every acceptance criterion parses as EARS (`WHEN`, `WHILE`, `IF … THEN`, `WHERE`, ubiquitous and combined forms; a failing one gets the closest template as its fix), that Out of Scope is not empty, that there are at most 3 `[NEEDS CLARIFICATION]` markers (the count is always in `data.needs_clarification`), that the constitution check names `constitution.md`'s version, covers every gate and justifies each violated gate in a complexity table, and that no avoided glossary term is used. Exit 1 on any finding; the glossary and constitution are optional when absent. Rules, grammar and the constitution format are in `docs/spec.md`.
- `anneal lint plan <file>`, `anneal plan approve <file>` and `anneal plan check <file>`, with the plan template (`plugin/playbooks/plan.template.md`) and its schema (`plugin/playbooks/schemas/plan.schema.json`). `lint plan` checks the spec link, the Goal, Tasks and Review focus sections, `### <id>: <title>` tasks each with `Files:`, one `Test:` command and `Blocked by:`, and that every blocker is another task with no cycle (exit 1 on any finding). `plan approve` refuses (exit 3, nothing recorded) while the plan fails its lint or its spec has any `[NEEDS CLARIFICATION]` marker, and otherwise records `plan_approved` with the `sha256:` hash of the plan. `plan check` exits 0 when the plan is approved and unchanged, 3 when it was never approved, and 4 when it changed since approval; it never creates a ledger. Test files (including `tests.rs`/`test.rs`), the plan and tree, `.temper/`, `.anneal/`, `tmp/`, `scratch/`, `*.md`/`*.txt`/`*.rst` and files in no git repository are always allowed. `anneal mode` has no `--store`: it writes to the ledger the hook reads. A denial is one `ERROR` line naming the missing precondition and the command that satisfies it, plus a `gate_blocked` event; with no mode the hook is silent and never creates a ledger. See `docs/preconditions.md`.
- `anneal repro record [--id <id>] [--timeout <secs>] [--session <id>] -- <command>`: runs a reproduction as `task done` runs a test command (no shell, output on stderr, 30 minutes by default) and appends `repro_red`, tagged with the worktree, only when it exits non-zero (exit 0). A command that exits 0 records nothing and exits 3; one that times out records nothing and exits 4 (a hang is not a reproduction); one that cannot start exits 2. The preconditions hook now counts only `repro_red` events tagged with the edited worktree, so a reproduction in a sibling worktree, or one appended by hand without a worktree, no longer unlocks diagnose mode. `anneal repro leftovers` lists each line holding a `[DEBUG-<id>]` tag in the files git knows of (tracked and untracked, not ignored) as `file:line` and exits 1 when there is one; it reads at most 1 MiB per file and 64 MiB in all, listing what it did not read under `skipped` (and `over_budget` when the total ran out). See `docs/preconditions.md`.

It blocks at most 2 times in a row per session (counted in `~/.anneal/stop-blocks.json`, reset by a tool call or a clean stop), does nothing when `stop_hook_active` is set, records each block as `stop_blocked`, and reports its own failures as one `ERROR` line. `anneal task done` now tags its events with the worktree, so only this worktree's runs count. It stops at the local pass. Its routing fixture is `evals/routing/verify.yaml`.
- `anneal decide --point <D1..D7> --question <noul|choice|score> --state <json> [--option <o>]...`: the Clef client every decision point will share. It routes D4 to `clef` and the other points to `clef-flash` (model ids in `plugin/playbooks/clef-thresholds.json`, with the blueprint's thresholds), applies the point's bands to the probability Clef returns (never to its `confidence`), and appends one row per call to `~/.anneal/decisions/decisions.jsonl` (outside the plugin's directories, so it survives a reinstall; rows capped at 8 KiB, the file rotated at 16 MiB keeping four old files). `clef_mode` is `off`, `shadow` or `enforce` with per-point overrides (`shadow,D1=off`), and a point stays in shadow for its first 50 answered decisions. Exit 0 with the action, 3 when Clef is off (no account, or mode `off`; nothing logged), 5 when Clef gives no answer within 2 s (the row records `unreachable`, and the envelope names the fallback: `ask` for D1, fail open for the others) or the account, token or mode is malformed (the envelope names the variable; nothing is logged). Choice options are 1 to 64 of `A-Z a-z 0-9 _ . : -`, and probabilities that do not sum to 1 within 0.05 count as a bad response. `anneal decide label <id> <outcome>` appends an outcome row. The token never appears in output, errors or the log. No HTTP client is bundled yet (a pending dependency decision), so every call currently exits 5. See `docs/decide.md`.
- `anneal calibrate [--point <D1..D7>] [--thresholds <file>]`: reads the decision log, rotated files included, and joins each answered decision to its latest `decide label`. For every point it reports n, the labelled n, the Brier score, 10 reliability bins with their observed frequency, the ask rate, and the threshold of the lowest band that minimises expected cost on the labelled set (a false accept costs 5, a needless intervention 1), proposed only when strictly cheaper than the current one. Each point gets a verdict: `stay-shadow` with fewer than 50 labelled decisions, a Brier score over 0.15 or an ask rate of 20% or more, else `eligible-to-enforce`; a question whose rule has no bands, such as D3's size, only records and never holds its point back. It writes every point's proposal to `~/.anneal/decisions/proposals.json` and lists the manual edits that would apply it (the thresholds file's JSON pointer and value, and the `clef_mode` override); it never applies them. The envelope goes to stdout, a short best-effort summary to stderr. Labels come only from `decide label` for now. See `docs/calibrate.md`.
- Clef D1 in `anneal hook guard`: after the denylist, a Bash command it did not deny is asked of Clef (`noul destructive_or_irreversible`) in process, sharing `decide`'s thresholds, modes, shadow period and decision log. In enforce mode 0.90 or more denies (rule `destructive`, with a `gate_blocked` event), 0.40 or more asks the human, and less defers; when Clef gives no answer, or D1 is set to enforce but cannot run (its anneal home, thresholds, counts or clock), the guard asks; an answer that cannot be logged keeps its deny or ask (a defer asks), so a log failure never lets a command through, and a Clef failure never denies. In shadow mode (the default) the would-be action is only logged and the verdict is unchanged; with Clef off nothing is asked. The command Clef gets and the row keeps (a new `input` field) is trimmed, cut to 1,024 characters and redacted wherever they appear, inside quotes and `bash -c` bodies too: the value of every `NAME=value` whose name looks like an environment variable (`FOO=bar`, `K[0]=v`, `K=(a b)`) or holds a credential word in any case (`api_token=x`), credential flag values (`--token=…`, `--password …`), comments and heredoc bodies become `<redacted>`, lowercase operands such as `dd of=` are kept, and anything after an unclosed quote or substitution is redacted. A deny after a slow Clef call skips the ledger record rather than overrun the hook's timeout, and says so. With no HTTP client yet every call is unreachable, so D1 stays in shadow and nothing changes for users. Automatic outcome labels (approve or deny on an ask, a revert within 24 h) are a follow-up. See `docs/guard.md`.
